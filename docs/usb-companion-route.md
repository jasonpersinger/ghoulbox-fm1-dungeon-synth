# USB 子機 (コンパニオン) への経路

BLE MIDI・外部ストレージ・マイク・無線を FM-1 本体に載せず、USB ホストになって **電池駆動の子機** (ESP32-S3 系、ネイティブ USB)
に任せる。本体の増分は約 10 KB / RAM 2〜4 KB。BLE スタック (240 KB + RAM 70 KB + 非公開バイナリ) とライセンス問題は子機側に移る。

## 前提 (ハード)

| 事実 | 影響 |
| --- | --- |
| **FM-1 は VBUS を出さない** (確認済) | 子機は電池駆動が必須。VBUS 無しで列挙できるデバイスのみ (ESP32-S3 のネイティブ USB は VBUS を見ない) |
| 子機候補は ESP32-S3 系 (AtomS3 / StampS3 など) | M5StickC / Plus / Plus2 の USB-C は UART ブリッジで USB デバイスになれない |
| USB コアは MUSB 互換 (hal/fm1_usb.h) | ホストモードの手順は MUSB 標準。ハブ無し単一デバイスなので MULTIPOINT 不要 |
| PHY に OTG 信号の CPU 強制ビットがある (`CPU_IDDIG`, `CPU_AVALID`, `CPU_SESSEND`, `CPU_VBUSVALID`, `HOST_DISC`) と D+/D- プルダウン・線状態読み出し | VBUS コンパレータに頼らずホストセッションを始められる。相手のプルアップでデバイス在席を判定できる |
| PC が繋がると VBUS が来る (充電検出あり)、子機では来ない | **VBUS の有無がそのまま PC / 子機の判別になる** |

## 判定 (起動時と抜き差し)

```
VBUS あり                  -> 今の装置モード (PC / 充電器)。D+ プルアップ、リセット/SOF 待ち。来なければ充電のみ
VBUS なし, D+ High が N 回  -> 子機候補: ホストセッション開始 (IDDIG=0, VBUSVALID 強制, SESSION), 列挙, 鍵の確認
VBUS なし, 線 Idle          -> 何も無し。周期再判定 (main loop, 数 100 ms 間隔; 既存 usb_retry の延長)
```

## 鍵による子機の確認

USB はホストが全ての転送を始めるので、「子機が最初に鍵を渡す」は **列挙直後の最初の IN 転送が鍵を運ぶ**として実装する:

1. 列挙: `GET_DESCRIPTOR` → `SET_ADDRESS` → `SET_CONFIG`。VID/PID と製品文字列で一次判定 (違えばホストモードを閉じて Idle)。
2. 最初の転送: ベンダ制御要求 `GET_KEY` (または最初のバルク IN)。子機は固定長の鍵 (例 16 B: マジック + プロトコル版 + 子機種別 + ノンス) を返す。
3. 鍵が一致しない / 200 ms 以内に来ない → セッション終了、Idle。以後その接続では再試行しない (抜き差しで再判定)。
4. 一致 → 子機プロトコル開始。鍵のノンスは以後のフレームのチェックに混ぜる (誤接続と古い子機の排除)。

鍵は秘密ではなく識別子。暗号化は要らない。本体側は鍵と対応プロトコル版の表を持ち、未知の版は拒否する。

## プロトコル (ベンダ固有バルク 1 対、クラスドライバは増やさない)

| 機能 | 本体 → 子機 | 本体側の受け口 |
| --- | --- | --- |
| ストレージ | `LIST`, `GET name` → `.fsmp` (スロット像) を 512 B フレームで | 既存の `SMP_WRITE` 経路で USR スロットへ。FAT は本体に無い |
| マイク | `MIC START/STOP` → 22.05 kHz 16 bit mono、512 B フレーム (44 KB/s) | スロットへ録音。モニタ用途ではない |
| 無線 MIDI (BLE / Wi-Fi) | 子機が BLE MIDI を終端 → MIDI バイト列 | `midi_event()` へ。送りは `midi_out_event()` の分岐 |
| 子機の状態 | `STATUS` → 電池、BLE 接続、ファイル数 | MENU の 1 行 |

フレーム: `[len u16][type u8][seq u8][payload][crc16]`。本体は 1 フレーム分のバッファ (512 B) だけ持つ。

## 本体の増分 (見込み)

| 部位 | Flash | RAM |
| --- | ---: | ---: |
| ホスト SIE (コントロール、バルク IN/OUT、CONN/DISC 割り込み) | 3 KB | EP バッファ 64 B × 3 |
| 列挙 + 鍵確認 | 1.5 KB | 64 B |
| OTG 判定の状態機械 | 1 KB | — |
| フレームとコマンド | 2 KB | 512 B |
| MIDI / スロット経路への接続、MENU 表示 | 2 KB | — |
| 合計 | **約 10 KB** | **2〜4 KB** |

ホストモード中は本体の USB MIDI / CDC / UAC は止まる (同じコア)。

## 先にやる実験 (各半日)

1. 装置モードを止め、プルダウン + `CPU_VBUSVALID` / `CPU_IDDIG` 強制でセッションを開始し、AtomS3 を挿して D+ High と CONN 割り込みが見えるか。
2. 列挙が通り、`GET_KEY` で鍵が返るか。
3. バルク IN/OUT ループバック 1 MB、音声 ISR を走らせたままエラー無しか (ISR の遅延は `cpu_q8` で見る)。

3 つ通れば本線 1.x の範囲で入る。通らなければ、ここで止める (本体側に代替は無い)。

## やらないこと

- 本体で MSC / UAC / HID のクラスドライバを書くこと (子機のプロトコル 1 本で済ませる)。
- 鍵の暗号化・認証。識別だけ。
- ハブ対応、複数子機。
