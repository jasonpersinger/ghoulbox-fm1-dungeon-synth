# エンジンを後から入れる (プラグイン) への経路

結論: **成立する**。この石はコードを Flash から直接実行する (XIP) ので、エンジンを Flash の空き領域に書き、`engine_t` の
関数ポインタで飛べばよい。RAM に展開しない。毎回ファームを焼き直す必要はない。規模は 2.0 級で、
**パート毎のエンジン状態の union 化** (6/8 トラック案と同じ土台) が前提。

## 根拠

- アプリは XIP 窓 (0x02000000..) で動き、ユーザーデータ領域 (0x93000..) も `fl_plain_window_init` で平文のまま XIP に見える。
  ユーザースロットと同じ場所にコードを置けばそのまま実行できる。
- エンジンは `engine_t` (name / page_title / edit[8] / presets / note_on / render / amp / desc / block / keys / done) で
  抽象化済み。`ENGINES[]` は append-only。プラグインは「この表 1 個 + 定数データ + コード」で完結する。
- 置き場所: 0xEA000–0xFC000 (72 KB、SDK の USR 領域、Felucca は未使用)。エンジン 1 本は 2〜5 KB
  (ANALOG 2.3、LOFI 2.1、PHASE 1.6、FM6 5.2、GRAIN 4.9、DRUM 8.5) なので 10 本以上。
- 書き込みは既存の `SMP_BEGIN / SMP_WRITE / SMP_END` と同型の `ENG_*` を SysEx に足すだけ。エディタの一覧から入れる。

## 設計

| 項目 | 内容 |
| --- | --- |
| パッケージ (`.feng`) | ヘッダ (マジック、ABI 版、エンジン名、要求 RAM、サイズ、CRC) + リンク済み像。スロット毎に固定アドレスでリンクし、再配置は持たない。エディタが空きスロットに合う像を選ぶ (プロジェクトが CI で全スロット分をビルド) |
| ABI | 本体が `felucca_api_t` (版番号 + 関数表: dsp ヘルパ、`SINE` 等の表、`voice_amp`、`mulq15`、`clamp`…、`track_t` の読み取り口) をプラグインの `init(api)` に渡す。プラグインは `engine_t *` を返す。版が違えば拒否。今は全部 static の 1 TU なので、この境界を切るのが作業の本体 |
| 呼び出し範囲 | XIP 内 (0x02000000..0x020FFFFF) は 23 bit の call 範囲内。関数ポインタ経由は絶対番地なので無関係 |
| **RAM** | 一番の制約。`voice_t.s[8]` / `ph[3]` だけで済むエンジンは即可。パート毎の静的状態 (GRAIN 28 KB、PHYS 51 KB、DRUM 7 KB) を持つものは、本体が「パート毎のエンジン用プール」を貸す。= エンジン状態の union 化 (研究メモの 6/8 トラック節)。プラグインのヘッダに要求 RAM を書き、超えるものは入れない |
| CPU | `target_budget.py` の網から外れる。本体の `cpu_q8` を見て、過負荷なら声を落とすガードを持つ。パッケージにホスト計測の instructions/sample を書き、エディタが警告する |
| 安全 | 壊れたプラグインは音声 ISR を落とす。既存のブートループガード (2 回失敗で UBOOT) に「直前に有効だったプラグインを次回は無効にして起動」を足す (.noinit に印) |
| 番号と互換 | エンジン番号 32〜63 をプラグイン用に予約し、スロット k に対応付ける。未導入のまま参照する保存物は `NO ENGINE` 表示で無音 (サンプルパックの `NO PACK` と同じ扱い)。工場プリセットはパッケージ内 |
| UI | `param_desc_t` のラベル・列挙名はプラグイン側の定数で、ポインタのまま使える。パラメータアイコンは `icons.c` がラベル名で選ぶので自動 |
| テスト | 同じ C をホストでもビルドし、regress の golden / CPU 検査に載せる。ABI ヘッダが契約 |
| ツールチェーン | 利用者はコンパイルしない。第三者は JieLi toolchain + ABI ヘッダで作れる (GPL) |

## Flash 節約としての効き

使用頻度の低いエンジン (SLICE 10 KB、WHEEL、TRIO、FORMANT、GRAIN、NOISE…) を基本像から外し「入れたい人が入れる」にすれば、
基本像はさらに 20〜30 KB 軽くなる。基本像 = コアエンジン + ローダ。

## 順番

1. エンジン状態の union 化 (RAM: 6/8 トラックとプラグインの共通土台)。
2. ABI の切り出し: dsp ヘルパと表を `felucca_api_t` にまとめ、既存エンジン 1 本 (LOFI など軽いもの) を「内蔵だが API 経由」で動かして契約を固める。
3. ローダ + スロット領域 + `ENG_*` プロトコル + セーフモード。
4. エディタの一覧と CI のパッケージビルド。
5. 内蔵エンジンの一部をパッケージへ移す。

## やらないこと

- 再配置可能コード (PIC) やダイナミックリンカ。スロット固定リンクで足りる。
- プラグインからのレジスタアクセス (hal/ 限定の原則どおり、純 DSP のみ)。
- プラグイン側での RAM の静的確保 (本体のプールを借りる)。
